= Issue #118 local Docker retest

Tested on 2026-11-21. Issue #118 remains reproducible: a database without Search connects successfully, then table discovery and CREATE TABLE surface raw `ERR unknown command 'FT._LIST'` errors without actionable compatibility guidance.

The updated Software Flex result differs materially from the October evidence: cursor-free aggregation, field loading, returned search fields, and numeric table creation now work. Normal connector scans still fail because they request `WITHCURSOR`.

The targeted reproduction harness passed its assertions, and the plugin package built successfully. This means the documented observations were reproduced; it does not mean issue #118 is fixed. The complete connector suite was not run. No Cloud target was contacted, so the Cloud Essentials tier behavior was not revalidated. The local control reproduces the absent-command condition only.

See link:retest-output.log[recorded evidence]. Preliminary runs on the repository's older pinned Software image were superseded by the final 8.2.6-58 run above.

== Changes needed for current Software Flex support

. Add a cached capability model and targeted execution probes. Command advertisement alone does not establish cursor support. Preserve ACL and connection errors separately, and make missing Search / unsupported-operation errors actionable (#118).
. Add a cursor-free scan reader. `RediSearchTranslator.aggregate` currently adds `WITHCURSOR` unconditionally; `RediSearchSession` and the page source rely on cursor reads and deletion. Disabling aggregation pushdown or setting cursor count to zero does not remove that dependency. Verify paging beyond one batch and server result limits before claiming complete scans.
. Gate planner pushdowns by proven capabilities. Initially let Trino perform unsupported filters, sorting, limits and aggregations over a correct raw-row reader; retain cursor-free server aggregation only where its semantics and result bounds are verified.
. Gate DDL and mutation behavior separately. Current Software Flex already accepts connector varchar and numeric table creation. The documented remaining restrictions include `FT.ALTER`, `FT.DROPINDEX ... DD`, `SORTABLE` index fields, some TAG query forms and cursors. Start with reads of existing indexes and explicitly reject unsupported operations; add safe schema-rebuild and owned-key deletion strategies only with dedicated tests.
. Test RAM and Flex independently, including large multi-page scans, cancellation, index readiness, exact numeric values, nulls, JSON restrictions, ACLs and unsupported operations. Preserve the existing RAM reader and execution plan as its own path.

This plan targets Software 8.2.6+ / Redis 8.8+ Search-on-Flex preview. It does not add Search to a deployment where the module is unavailable. No production connector changes were made in this retest.

== Rerun locally

From the repository root:

[source,bash]
----
bash benchmarks/issue-118/run.sh > /tmp/issue118-retest.log 2>&1
----

The script refreshes `redislabs/redis:latest` and recreates only its four named test containers. It uses existing local `redis:8.4` and `trinodb/trino:483` images, downloading them if absent. It runs a temporary Maven reproduction class, packages the plugin, mounts it into Trino Docker, and runs SQL through the CLI inside that container. The temporary test source is removed on exit. The harness is stored outside the ordinary test source tree because it requires these explicitly provisioned endpoints.

All published ports bind to loopback. The management API uses fixed synthetic credentials solely for this isolated test cluster. The test containers remain available for inspection:

* `trino-issue118-software`: management API 19443; RAM 12018; Flex 12019.
* `trino-issue118-no-search`: 12020.
* `trino-issue118-acl`: 12021.
* `trino-issue118-trino`: Trino 18018.

To remove them:

[source,bash]
----
docker rm -f trino-issue118-trino trino-issue118-software trino-issue118-no-search trino-issue118-acl
----
